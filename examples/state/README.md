# Resource reservation references

Both scenarios embed the same exact `lce.resource-reservation@1.0.0` machine, `lce.reserve-available@1.0.0` pure reducer and `lce.reservation-data@1.0.0` data contract. Pharmacy stock starts with five primary and three partner units; school-library stock starts with four primary and two partner copies. The first primary reservation consumes two pharmacy units or one library copy. All quantities are synthetic.

```sh
go run ./cmd/statecheck examples/state/resource-reservation.machine.json
go run ./cmd/statecheck --lock examples/state/resource-reservation.lock.json
go run ./cmd/statecheck --run examples/state/pharmacy-reservation.run.json
go run ./cmd/statecheck --run examples/state/library-reservation.run.json
```

Each instance owns durable `tenantId`, `resourceId` and `available` slots, plus volatile `acceptedSinceRestart`. The primary volatile baseline is zero; the partner overrides it to ten to demonstrate reset to the effective instance initialization. Command IDs belong to the scenario envelope. A typed `ReservationCommand` carries tenant, resource and quantity. An accepted command changes availability and the volatile counter, advances revision and records a typed reservation-notice intent. A denied command records its response without changing owned state or revision.

The reducer checks target identity, positive quantity and nonnegative sufficient stock. It selects a safe zero-or-requested delta before subtraction, so rejected extreme negative quantities do not overflow an unused eager branch. The embedded pure tests have handwritten expected values for acceptance, shortage, wrong tenant/resource, zero and extreme negative quantities, and invalid initial stock. Identifier matching here does not authenticate the caller or enforce production tenancy.

## Independent scenario oracle

Both scenarios have the following eighteen ordered steps. The expected results below are calculated directly from the declared quantities and protocol; they are not generated by running the reducer.

| Step | Instance and action | Expected result |
| --- | --- | --- |
| 0 | Primary `reserveA`, first quantity, revision 0 | Commit; available 3, counter 1, revision 1 |
| 1 | Partner `reserveA`, quantity 1, revision 0 | Commit independently; counter 11, revision 1 |
| 2 | Retry primary `reserveA`, inject `before_commit` | Replay original receipt; injected fault bypassed |
| 3 | Primary `reserveB`, quantity 4, revision 1 | Denied; historical remaining 3; revision stays 1 |
| 4 | Primary `reserveC`, quantity 1, revision 1, `before_commit` | Roll back; available 3 and counter 1 unchanged; no receipt |
| 5 | Restart primary | Available 3, revision 1 and receipts survive; counter resets to 0 |
| 6 | Retry primary `reserveC`, `after_commit_before_reply` | Commit; available 2, counter 1, revision 2; reply lost |
| 7 | Restart primary | Available 2 and revision 2 survive; counter resets to 0 |
| 8 | Retry primary `reserveC`, same post-commit fault | Replay counter 1 from original receipt; current counter stays 0; fault bypassed |
| 9 | Primary `reserveD`, quantity 2, revision 2 | Commit; available 0, counter 1, revision 3 |
| 10 | Primary `reserveE`, quantity 1, revision 3 | Denied; remaining 0; revision stays 3 |
| 11 | Retry primary `reserveB`, original revision 1 | Replay denied receipt with remaining 3; current availability stays 0 |
| 12 | Primary `reserveA`, changed quantity | ID conflict; no change |
| 13 | Primary `reserveF`, stale revision 2 | Revision conflict; no receipt or change |
| 14 | Restart partner | Durable availability survives; counter resets to overridden baseline 10 |
| 15 | Retry partner `reserveA`, original revision 0 | Replay original counter 11; current counter stays 10 |
| 16 | Partner `reserveB`, primary tenant, revision 1 | Wrong-target denial; no revision or state change |
| 17 | Partner `reserveC`, quantity 1, revision 1 | Commit; counter 11, revision 2 |

| Final instance | Available | Volatile counter | Revision | Receipts | Effect intents |
| --- | ---: | ---: | ---: | ---: | ---: |
| Primary, both domains | 0 | 1 | 3 | 5 | 3 |
| Pharmacy partner | 1 | 11 | 2 | 3 | 2 |
| School-library partner | 0 | 11 | 2 | 3 | 2 |

There are nine pure evaluations, including the rolled-back proposal. Each uses twenty-one primitive operations and one invocation: 189 operations and nine invocations in total. Replays and conflicts perform no pure evaluation. The five effect intents belong to the five accepted commands; no delivery or acknowledgement occurs.

Every run initializes fresh instances. Durable state here survives only the explicitly modeled restarts inside that run. Saved PostgreSQL evidence is an immutable experiment snapshot, not a live reservation service, inventory database or external business transaction.
